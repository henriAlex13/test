🔧 1. Documentation Technique

Architecture, composants et fonctionnement interne du système

1.1 Architecture générale

Le système repose sur deux blocs indépendants :

  1. Le module de traitement : fonctions Python qui lisent les fichiers texte SWIFT (MTx99), extraient les champs pertinents, appliquent la détection de mots-clés RFI/Sanctions, et génèrent un classeur Excel à trois feuilles.
  2. Le module de surveillance : basé sur la librairie watchdog, il observe en continu l'arborescence Data/<mois>/<date>/ et déclenche le traitement dès qu'un dossier contient exactement 2 fichiers .txt non encore traités.
1Dossier de date reçoit fichiers TXT
2watchdog détecte l'événement
3Vérification : 2 fichiers + non traité
4Exécution du traitement SWIFT
5Génération du fichier .xlsx

Structure attendue sur disque :

Data/
├── novembre/
│   ├── 01112025/
│   │   ├── xxx_recu.txt
│   │   └── xxx_emi.txt
│   └── 02112025/...
└── décembre/
    ├── 01122025/...
    └── 31122025/...

1.2 Composants du traitement

Handler de surveillance

La classe TxtFileHandler (héritée de FileSystemEventHandler) réagit aux événements on_created et on_modified. Elle applique la règle de déclenchement :

if len(fichiers_txt) == 2 and str(dossier) not in self.dossiers_traites:
    # lancer le traitement
    self.dossiers_traites.add(str(dossier))
Pourquoi un set() en mémoire ?
Il mémorise les dossiers déjà traités pendant l'exécution du script, afin d'éviter un retraitement à chaque modification détectée sur les mêmes fichiers. Cette mémoire est réinitialisée à chaque redémarrage du script.

1.3 Flux d'exécution détaillé

  1. Démarrage du script → scan initial de tous les dossiers existants (traite ceux déjà complets).
  2. L'Observer watchdog s'attache récursivement au dossier racine Data/.
  3. À chaque écriture/copie de fichier .txt, un événement est émis.
  4. Le handler attend 2 secondes (anti-fichier-incomplet), puis liste les .txt du dossier concerné.
  5. Si exactement 2 fichiers et dossier non traité → appel de la chaîne de traitement (open_and_convert_file → extraction champs → nettoyage texte → filtre RFI → fusion → export Excel).
  6. Le fichier RFI_FAhd_<date>.xlsx est écrit dans le même dossier, avec 3 feuilles : MTx99_received, MTx99_sent, Merged_data.
  7. Le dossier est marqué comme traité pour la session en cours.

1.6 Points d'extension possibles

  • Historique persistant : remplacer le set() en mémoire par un fichier JSON pour survivre aux redémarrages.
  • Journalisation : ajouter des logs horodatés dans un fichier plutôt que sur la sortie standard.
  • Notification : envoi d'un e-mail ou message Teams en cas de détection RFI positive.
  • Tolérance aux erreurs : ré-essai automatique si un fichier est encore verrouillé par une copie en cours.
  • Exécution en service : transformer le script en tâche planifiée (Task Scheduler) ou service Windows pour un démarrage automatique au boot.

📘 2. Guide Utilisateur

Comment utiliser l'outil au quotidien — aucune connaissance en programmation nécessaire

2.1 À quoi sert cet outil ?

Chaque jour, des fichiers SWIFT (messages reçus et émis) arrivent dans des dossiers datés. Cet outil surveille automatiquement ces dossiers et, dès que les 2 fichiers nécessaires sont présents, génère automatiquement un fichier Excel contenant les messages liés aux mots-clés RFI/Sanctions — sans aucune action manuelle de votre part.

2.2 Préparation (une seule fois)

1

Installer Python et les librairies nécessaires

Si ce n'est pas déjà fait, ouvrez une invite de commande et exécutez :

pip install pandas numpy scikit-learn watchdog openpyxl
2

Vérifier le fichier des mots-clés

Le fichier mots_cles_rfi.txt contient la liste des mots à rechercher (un mot par ligne). Vous pouvez l'ouvrir avec le Bloc-notes et l'éditer librement :

# === SANCTIONS ===
Sanc
Embargo

# === TERRORISME ===
terrorism
Les lignes commençant par # sont des commentaires : elles servent à organiser la liste mais ne sont pas utilisées comme mots-clés.
3

Vérifier le chemin du dossier surveillé

Assurez-vous que la variable DOSSIER dans le script pointe bien vers votre dossier Data (ex : E:\Décembre 2025).

2.3 Utilisation quotidienne

1

Lancer la surveillance

Double-cliquez sur le fichier .bat fourni, ou lancez manuellement :

python surveillance_avec_mots_cles.py

Une fenêtre s'ouvre et reste active — c'est normal, elle surveille en continu. Ne la fermez pas tant que vous voulez que la surveillance fonctionne.

2

Déposer les fichiers du jour

Placez les 2 fichiers .txt du jour (celui contenant "recu" et celui contenant "emi" dans leur nom) dans le dossier de la date correspondante.

3

Laisser l'outil travailler

Dès que les 2 fichiers sont détectés, un message s'affiche dans la fenêtre et le traitement démarre automatiquement. Quelques secondes plus tard, le fichier Excel apparaît dans le même dossier.

4

Récupérer le résultat

Le fichier généré s'appelle RFI_FAhd_<date>.xlsx et contient 3 onglets :

OngletContenu
MTx99_receivedMessages reçus correspondant aux mots-clés recherchés
MTx99_sentEnsemble des messages émis (nettoyés)
Merged_dataRapprochement entre messages reçus RFI et messages émis liés

2.4 Arrêter la surveillance

Cliquez dans la fenêtre du script puis appuyez sur Ctrl + C, ou fermez simplement la fenêtre.

2.5 Dépannage rapide

Le fichier Excel n'est pas généré : vérifiez que les 2 fichiers TXT sont bien présents en même temps dans le dossier, et que leurs noms contiennent bien "recu" et "emi".
Un dossier n'est pas retraité alors que j'ai remplacé un fichier : c'est normal — un dossier déjà traité pendant la session en cours n'est pas retraité automatiquement. Redémarrez le script pour forcer un nouveau passage.
Message d'erreur au démarrage : vérifiez que le chemin du dossier DOSSIER existe bien et que les librairies Python sont installées (étape 1 de la préparation).

💾 3. Guide de Sauvegarde

Que sauvegarder, à quelle fréquence, et comment restaurer le système

3.1 Pourquoi sauvegarder ?

Le système repose sur trois types d'éléments : le code, la configuration, et les données produites. Une panne disque, une suppression accidentelle ou un changement de poste ne doivent pas faire perdre l'historique des traitements RFI.

3.2 Que sauvegarder

ÉlémentFichier(s)PrioritéPourquoi
Script de traitement surveillance_avec_mots_cles.py Haute Cœur du système ; sans lui, plus d'automatisation possible.
Fichier de mots-clés mots_cles_rfi.txt Haute Contient la liste métier des ~200 mots-clés RFI/Sanctions ; leur perte oblige à tout reconstituer.
Script de lancement lancer_surveillance_swift.bat Moyenne Facilite le redémarrage, mais reconstituable rapidement.
Fichiers TXT sources Data/<mois>/<date>/*_recu.txt, *_emi.txt Haute Données brutes originales ; nécessaires pour tout retraitement futur.
Fichiers Excel générés Data/<mois>/<date>/RFI_FAhd_*.xlsx Moyenne Régénérables à partir des TXT sources, mais utile de garder l'historique produit sans avoir à relancer.
Documentation Ce document HTML Basse Utile pour la continuité si une autre personne reprend le système.

3.3 Fréquence recommandée

ÉlémentFréquence
Script + mots-clés + documentationÀ chaque modification (versionnage)
Fichiers TXT sources et Excel générésQuotidienne, à la fin de journée de traitement

3.4 Méthode simple : copie manuelle

La méthode la plus directe consiste à copier périodiquement le dossier complet vers un emplacement de sauvegarde (disque réseau, disque externe) :

xcopy "E:\Décembre 2025" "\\ServeurBackup\SWIFT\Décembre 2025" /E /I /Y

La commande xcopy avec /E copie tous les sous-dossiers, /I évite les questions de confirmation, /Y écrase sans demander.

Sauvegarde automatique quotidienne (Windows)

Créez une tâche planifiée qui exécute chaque soir un script .bat :

@echo off
set DATE_JOUR=%date:~-4,4%%date:~-7,2%%date:~-10,2%
xcopy "E:\Décembre 2025" "D:\Backup_SWIFT\%DATE_JOUR%" /E /I /Y
echo Sauvegarde terminée le %DATE_JOUR% >> D:\Backup_SWIFT\journal_backup.log

3.5 Méthode alternative : archive compressée

Pour limiter l'espace disque, une archive .zip horodatée peut être créée avec PowerShell :

Compress-Archive -Path "E:\Décembre 2025" -DestinationPath "D:\Backup_SWIFT\Decembre2025_$(Get-Date -Format yyyyMMdd).zip"

3.6 Bonnes pratiques

  • Règle 3-2-1 : conserver au moins 3 copies des données, sur 2 supports différents, dont 1 hors site (serveur réseau ou cloud d'entreprise).
  • Ne jamais sauvegarder par-dessus la même copie : privilégier des dossiers ou archives horodatés pour pouvoir revenir en arrière.
  • Tester la restauration régulièrement, pas seulement la sauvegarde.
  • Protéger l'accès aux sauvegardes contenant des données SWIFT, données sensibles à caractère bancaire.
Sensibilité des données : les fichiers SWIFT et les fichiers Excel RFI contiennent des informations financières et potentiellement liées à des sanctions. Les sauvegardes doivent être stockées sur des emplacements conformes à la politique de sécurité de votre établissement, avec accès restreint.

3.7 Procédure de restauration

  1. Identifier la sauvegarde la plus récente et cohérente (vérifier la date dans le nom du dossier/archive).
  2. Copier (ou extraire) le contenu vers l'emplacement de travail habituel (E:\Décembre 2025 ou équivalent).
  3. Vérifier la présence du script surveillance_avec_mots_cles.py et de mots_cles_rfi.txt.
  4. Relancer le script de surveillance pour reprendre l'automatisation normalement.
