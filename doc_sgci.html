Présentation

Vue d'ensemble

La plateforme regroupe deux modules distincts accessibles depuis une page d'accueil centrale :

📊
Dashboard Réclamations
Analyse des réclamations clients : évolution mensuelle, répartition par agence, nature, délai et SLA. Chargement par upload de fichier CSV ou Excel.
📈
Module KPI
Tableau de bord des indicateurs de performance : CRC, Satisfaction client (SAT) et SAT PRO. Historisation mensuelle en SQLite avec export Excel stylé.
Technique

Architecture de l'application

Navigation entre les pages

L'application n'utilise pas de routing URL. Les trois pages (Accueil, Dashboard, Module KPI) sont toutes présentes dans le DOM simultanément et alternent entre display: block et display: none via un callback de navigation. Ce choix évite les problèmes de session et de rechargement de page.

Installation et démarrage

Prérequis

# Python 3.9+ requis
pip install dash dash-bootstrap-components pandas plotly openpyxl unidecode numpy gunicorn

Guide utilisateur

Dashboard Réclamations

Chargement des données

1
Préparer le fichier

Fichier CSV ou Excel (.xlsx) exporté depuis le système de réclamations. Les données doivent commencer à la ligne 8 (header=7).

2
Uploader le fichier

Glisser-déposer ou cliquer sur la zone d'upload dans la sidebar gauche. Un message de confirmation indique le nombre de lignes chargées.

3
Appliquer les filtres

Utiliser les filtres (Ticket, Agence, Année, Mois, Segmentation, Délai) pour affiner l'analyse. Cliquer sur Réinitialiser pour tout effacer.

KPI cards

En haut de chaque vue, 4 indicateurs clés sont affichés :

📋 Total réclamations
Nombre de références uniques dans la période sélectionnée.
⚠️ Hors délai
Réclamations dont le traitement dépasse 30 jours.
✅ Fondées
Réclamations classées FONDEE (avec ou sans faute SG).
📊 Taux hors délai
Pourcentage de réclamations hors délai sur le total.

Panneau de débogage

En bas de la zone principale, un panneau 🔍 Logs de débogage (cliquable pour déplier) affiche les détails de chaque upload : taille du fichier, nombre de lignes parsées, valeurs des colonnes calculées. Utile en cas d'anomalie sur un fichier.

⚠️

Taille max : 50 MB par fichier. Pour les fichiers plus volumineux, contacter l'équipe Data Engineering pour adapter la configuration serveur.

Guide utilisateur

Module KPI

Le Module KPI permet d'importer et d'historiser mensuellement trois types de fichiers de performance.

Procédure d'import mensuel

🚨

Étape obligatoire : sélectionner le mois et l'année de référence avant tout upload. Si vous uploadez sans avoir sélectionné le mois/année, le fichier sera rejeté et vous devrez le re-charger (plus besoin d'actualiser la page).

1
Sélectionner le mois et l'année

Dans la sidebar, choisir le mois (ex : Avril) et l'année (ex : 2026) correspondant aux données à importer.

2
Uploader les fichiers

Glisser chaque fichier dans sa zone dédiée : 📞 KPI CRC, 😊 KPIS SAT, ⭐ KPIS SAT PRO. Un message vert confirme le chargement.

3
Consulter les données

Naviguer entre les 3 onglets. Utiliser le filtre Mois pour afficher un mois spécifique, ou laisser vide pour voir l'historique complet.

Onglet 📞 KPI CRC

Indicateurs du Centre de Relation Client : taux de joignabilité, occupation, écoute, réponse à la 1ère demande, etc.

  • KPI cards pour les 5 indicateurs clés du dernier mois
  • Tableau historique (indicateur × mois)
  • Graphique d'évolution des taux clés

Onglets 😊 Satisfaction et ⭐ SAT PRO

Les deux onglets partagent la même structure d'affichage. Chaque onglet présente des sous-onglets correspondant aux feuilles du fichier Excel uploadé.

  • Graphique barres groupé par UC (couleur par UC)
  • Tableau avec lignes UC en orange et agences alternées
  • Filtres UC → Agences en cascade

ℹ️

La contrainte UNIQUE + INSERT OR REPLACE permet de réimporter un même mois sans créer de doublons — les données existantes sont simplement mises à jour.

Sauvegarde

Il est recommandé de copier régulièrement le fichier kpi_historique.db vers un emplacement sécurisé (serveur de fichiers, SharePoint, etc.). En cas de perte, les données historiques ne peuvent pas être reconstituées automatiquement.

# Exemple de sauvegarde manuelle
cp kpi_historique.db backup/kpi_historique_$(date +%Y%m%d).db
Référence technique

Parsers de fichiers

Logique commune de détection des données

Tous les parsers appliquent la même règle pour ignorer les lignes d'en-tête intermédiaires :

✅

Règle de filtrage : toute ligne dont les colonnes de données (hors colonne A/entité) ne contiennent aucune valeur numérique ou pourcentage est ignorée. Cela élimine automatiquement les titres, sous-titres et séparateurs.

parse_crc — KPI CRC.xlsx

ColonneContenu attendu
A (ignorée)Peut être vide
BNom de l'indicateur
CObjectif
D, E, F...Valeurs par mois (la dernière colonne non-vide est prise comme valeur du mois importé)

parse_sat / parse_sat_pro — KPIS SAT & SAT PRO

ColonneContenu attendu
ANom de l'entité (UC ou agence) — normalisé en MAJUSCULES
B, C, D...Valeurs par mois (la dernière colonne non-vide est prise)

Le parser traite toutes les feuilles du fichier Excel. Chaque feuille devient un sous-onglet dans l'interface.

⚠️

Les noms des entités dans les fichiers Excel doivent correspondre exactement (en majuscules) aux noms définis dans UC_MAPPING et AGENCE_TO_UC pour que le rattachement UC fonctionne correctement.

Référence technique

Dépannage

Problèmes fréquents

L'upload de fichier ne fait rien

⚠️

Vérifier dans le panneau debug (⚡ Tester les callbacks) que openpyxl est bien installé. Si le fichier dépasse 50 MB, augmenter MAX_CONTENT_LENGTH dans le code.

Les en-têtes apparaissent dans les données KPI

ℹ️

Le parser filtre automatiquement les lignes sans valeur numérique. Si des en-têtes passent quand même, vérifier que la ligne d'en-tête ne contient pas accidentellement des chiffres.

Les agences n'ont pas de UC rattachée

ℹ️

Le nom de l'agence dans le fichier Excel ne correspond pas exactement au nom dans UC_MAPPING. Vérifier la casse (tout en MAJUSCULES) et les espaces/accents.

L'export Excel n'a pas de style

ℹ️

Vérifier que openpyxl >= 3.1 est installé. L'export utilise une approche en 2 passes (écriture puis stylisation) qui nécessite cette version.

SAT PRO affiche "Importez le fichier SAT"

⚠️

Supprimer le fichier kpi_historique.db et relancer l'application pour forcer la recréation des tables. Réimporter ensuite les fichiers.

L'application ne démarre pas avec Gunicorn

🚨

Vérifier que la ligne server = app.server est bien présente dans le code, et que la commande Gunicorn référence reclam_final:server (nom du fichier sans .py, deux-points, nom de la variable).
