Dashboard KPI — Documentation & Guide d'utilisation

Application de collecte et de suivi des indicateurs de pilotage (Streamlit + SQLite).

À qui s'adresse ce document ? La partie Guide (sections 1 à 8) est destinée aux utilisateurs de l'outil. La partie technique (sections 9 à 20) est destinée à l'administrateur / au backup chargé de la maintenance en cas d'absence.

1. Présentation GUIDE

Le Dashboard KPI centralise la saisie, le suivi et la consolidation des indicateurs de performance. Chaque indicateur (KPI) appartient à un domaine (Activités commerciales, Performance financière, etc.), relève d'une direction et possède une périodicité (mensuelle ou trimestrielle). Les contributeurs saisissent les valeurs de leurs indicateurs ; l'administrateur consolide l'ensemble.

2. Connexion GUIDE

  1. Ouvrez le navigateur à l'adresse communiquée par l'administrateur, généralement http://localhost:8501 (ou l'adresse du serveur).
  2. Saisissez votre identifiant et votre mot de passe, puis cliquez sur Se connecter.
  3. Le menu de gauche s'adapte à votre rôle. Le bouton Se déconnecter est en bas de ce menu.
Compte par défaut Identifiant admin — mot de passe admin123 (à changer rapidement).

4. Saisir des indicateurs GUIDE

Page Saisie (utilisateur) ou onglet Saisie de la page Pilotage (admin) :

  1. Choisissez la périodicité, l'année puis le mois (ou le trimestre).
  2. Les indicateurs concernés s'affichent, regroupés par domaine, sur deux colonnes. L'unité attendue est rappelée entre parenthèses : %, FCFA ou Nombre. La direction responsable apparaît en infobulle (icône ?).
  3. Renseignez les valeurs, ajoutez un commentaire si besoin, puis cliquez sur 💾 Enregistrer.
Corrections Une valeur déjà saisie pour une période est pré-remplie : il suffit de la modifier et d'enregistrer à nouveau. Chaque enregistrement (y compris les corrections) est tracé dans l'historique.

5. Tableau de bord GUIDE

Filtrez par domaine et par direction. Vous obtenez :

  • des indicateurs de synthèse (nombre de KPIs, taux de remplissage) ;
  • un tableau des valeurs pour une période de référence ;
  • la courbe d'évolution d'un indicateur au choix ;
  • un bouton d'export CSV.

6. Historique GUIDE

Journal complet des enregistrements : date/heure, KPI, domaine, direction, période, valeur, contributeur et commentaire. Filtres par domaine, contributeur et période, avec export CSV. L'historique conserve toutes les saisies, y compris les valeurs remplacées.

7. Espace administrateur GUIDE

Pilotage

Quatre onglets en un seul endroit : Vue d'ensemble (consolidation de tous les indicateurs, complétude par domaine), Analyse (tableau de bord), Historique et Saisie.

Référentiel

Liste des indicateurs et de leurs responsables. En bas, le formulaire ➕ Ajouter un indicateur permet de créer un KPI (intitulé, domaine existant ou nouveau, direction, périodicité, contact, responsable).

Comptes

  • Créer un compte et lui affecter directement ses KPIs.
  • Modifier / supprimer un compte : nom, rôle, réinitialisation du mot de passe, ou suppression (avec confirmation). Impossible de supprimer son propre compte ni le dernier administrateur.
  • Modifier les affectations d'un compte existant.
Modèle d'affectation Un indicateur a un seul responsable. Affecter un KPI à un utilisateur le retire automatiquement de son précédent responsable.

8. Direction Générale GUIDE

Le rôle dg dispose d'une page dédiée, actuellement en cours de conception (« Bientôt disponible »). Son contenu sera défini ultérieurement.

9. Architecture TECH

Application Streamlit (Python) mono-fichier (app.py), stockage SQLite local (kpi_data.db). Aucune dépendance serveur externe. Les CSV ne servent qu'à l'amorçage initial de la base.

Navigateur ──HTTP──► Streamlit (app.py) ──► SQLite (kpi_data.db)
                         │
                         └─ amorçage 1er lancement ◄── referentiel_kpi.csv, users.csv

11. Installation & lancement TECH

Prérequis : Python 3.9+. Dans le dossier du projet :

pip install -r requirements.txt
streamlit run app.py

L'application s'ouvre sur http://localhost:8501. Pour un accès depuis d'autres postes du réseau :

streamlit run app.py --server.address 0.0.0.0 --server.port 8501

13. Amorçage & import CSV TECH

Au démarrage, init_db() crée les tables si nécessaires puis, uniquement si une table est vide, l'amorce depuis le CSV correspondant. La lecture CSV détecte automatiquement le séparateur (, ou ;) et gère l'encodage UTF-8/BOM.

Appliquer de nouvelles données CSV : les modifications d'un CSV ne sont reprises que sur une table vide. Pour repartir des CSV, fermez l'application, supprimez kpi_data.db, puis relancez — la base est ré-amorcée.

Attention Supprimer kpi_data.db efface aussi les saisies et l'historique. À ne faire que sur une base de test ou après sauvegarde (§17).

Format attendu du referentiel_kpi.csv (en-têtes exacts) :

categorie,kpi,periodicite,direction,contact,username

14. Affectations TECH

L'affectation est portée par la colonne referentiel.username : un KPI = un responsable. Un utilisateur saisie voit les KPIs dont username vaut son identifiant. Les rôles admin et dg voient tous les KPIs. La gestion se fait via la page Comptes (à la création ou via « Modifier les affectations »).

15. Sécurité TECH

  • Les mots de passe ne sont jamais stockés en clair : SHA256(SALT + mot_de_passe).
  • Le sel est défini dans app.py : SALT = "SGCI-KPI-2026".
À faire en production Modifier le SALT et, idéalement, le déplacer dans st.secrets ou une variable d'environnement. Changer le SALT invalide tous les mots de passe existants : il faut alors recréer les comptes (ou réinitialiser les mots de passe).

17. Sauvegarde & restauration TECH

Toutes les données de production sont dans kpi_data.db.

  • Sauvegarde : copiez régulièrement kpi_data.db (application fermée de préférence) vers un emplacement sûr, en datant le fichier (ex. kpi_data_2026-06-19.db).
  • Restauration : remplacez kpi_data.db par la copie sauvegardée, puis relancez.
  • Pensez aussi à archiver app.py et les CSV d'amorçage.

19. Évolutions possibles TECH

  • PostgreSQL pour un usage multi-utilisateurs simultané (adapter get_conn).
  • Externaliser le SALT et les accès via st.secrets.
  • Concevoir la vue Direction Générale.
  • Édition en ligne du champ contact et renommage d'identifiant.

20. Checklist backup (en cas d'absence) TECH

  1. Lancer l'appli : streamlit run app.py depuis le dossier du projet.
  2. Vérifier que la page Référentiel affiche bien les indicateurs.
  3. Sauvegarder kpi_data.db quotidiennement (copie datée).
  4. Gestion des accès : page Comptes (créer / modifier / supprimer, affecter les KPIs).
  5. Ajout d'un indicateur : page Référentiel → formulaire en bas.
  6. En cas de problème d'affichage des KPIs : voir §18 (souvent un souci de CSV).
